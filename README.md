# Репостер Telegram → ВКонтакте

Бот копирует новые сообщения кураторов из закрытого чата Telegram в закрытую группу ВКонтакте. История чата не переносится. Каждый пост выходит от имени сообщества и начинается с автора того, кто отправил сообщение в учебный чат.

Для закрытой группы нужен пользовательский клиент Telegram (Telethon): обычный бот туда не добавить, если в чат не пускают ботов. В ВК публикация идёт ключом сообщества через `wall.post` с `from_group=1`.

## Как выглядит пост

Сообщение с текстом:

```text
Автор: Анна Смирнова

Конспект к семинару. Файл во вложении.
```

Только фото или файл, без подписи:

```text
Автор: Анна Смирнова
```

Если фамилии в профиле нет, в шапке остаётся имя. Пересланное сообщение подписывается куратором, который переслал его в чат, а не исходным автором.

Сообщения людей вне `ALLOWED_TG_USER_IDS` пропускаются.

## Что переносится

| В Telegram | В ВК |
| --- | --- |
| Текст | Текст поста по шаблону выше |
| Фото, в том числе альбом | Одно вложение `photo` на каждое фото, альбом — одной записью |
| PDF, DOC, ZIP и прочие файлы | Вложение `doc`, загруженное на стену |
| Обычное видео | Вложение `video` той же записью |
| Голосовые и видео-кружки | Не публикуются, в логе warning |
| Стикеры, музыка, опросы, геоточки | Не публикуются, в логе warning |

Альбом Telegram приходит как несколько отдельных событий с одним `grouped_id`. Скрипт копит их в памяти и ждёт тишину 2,5 секунды (`ALBUM_QUIET_SECONDS`). Если части всё ещё приходят, пост уходит не позже чем через 12 секунд (`ALBUM_MAX_WAIT_SECONDS`). Пауза сделана через `asyncio.sleep` в отдельной задаче: сон внутри обработчика задержал бы остальные фото альбома.

`vk_api` блокирует поток. Загрузка файлов и `wall.post` вызываются через `asyncio.to_thread`, поэтому Telethon в это время продолжает получать сообщения. Ошибка одного поста пишется в лог и не останавливает процесс.

Правки и удаления в Telegram повторно в ВК не отправляются. Уже опубликованные id лежат в `posted_ids.json` рядом с сессией, чтобы повторная доставка апдейта не создала дубль.

## Файлы

```text
main.py              запуск, сигналы остановки, проверка чата
config.py            чтение .env
tg_handler.py        фильтр кураторов, буфер альбомов, скачивание
vk_poster.py         загрузка фото, документов, видео и wall.post
.env.example         шаблон окружения
requirements.txt
Dockerfile
docker-compose.yml
```

Сессия Telegram (`reposter.session`) и журнал id пишутся в `sessions/` локально и в том `./sessions` в Docker. Это полный вход в аккаунт: каталог не коммитьте и не отдавайте.

## 1. Telegram

1. Заведите отдельный аккаунт и добавьте его в закрытую группу. Сессия даёт доступ ко всему аккаунту, личный номер для этого лучше не использовать.
2. На [my.telegram.org](https://my.telegram.org) откройте API development tools и возьмите `API_ID` и `API_HASH`.
3. `PHONE` — номер этого аккаунта в формате `+79991234567`. Если включён облачный пароль, запишите его в `TG_2FA_PASSWORD`.
4. `TG_CHAT_ID` — id супергруппы, он начинается с `-100`. Его видно в ссылке веб-клиента (`https://web.telegram.org` → чат → фрагмент `#-100...`). При старте скрипт пишет название чата: так можно проверить, что id верный.
5. `ALLOWED_TG_USER_IDS` — числовые id кураторов через запятую. Узнать id можно через `@userinfobot` или один запуск с `LOG_LEVEL=DEBUG`: пропущенные отправители пишутся в лог вместе с id.

## 2. ВКонтакте

1. Ключ создаётся в сообществе: Управление → Настройки → Работа с API → Создать ключ.
2. Отметьте права: стена, фотографии, документы, видео, сообщества.
3. Вставьте ключ в `VK_TOKEN`.
4. `VK_GROUP_ID` — число из адреса сообщества **без минуса** (`vk.com/club123456789` → `123456789`). Минус скрипт добавляет сам: стена публикуется в `owner_id=-123456789` от имени группы (`from_group=1`).

Ключ сообщества с этими правами обычно достаточен. Если ВК ответит ошибкой 27 (метод недоступен ключу сообщества) на документы или видео, выпустите пользовательский ключ администратора с теми же правами и подставьте его в `VK_TOKEN`.

## Локальный запуск

Нужен Python 3.10 или новее.

```powershell
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`, затем:

```powershell
python main.py
```

В первый раз Telegram пришлёт код входа. Файл сессии появится в `sessions/reposter.session`. Следующие запуски код не спрашивают. Остановка — Ctrl+C: уже собранный альбом будет дописан в ВК.

## Запуск на VPS

На сервере нужны Docker и Docker Compose. Порты наружу открывать не нужно: контейнер сам ходит в Telegram и ВК.

```bash
cp .env.example .env
# заполните .env
docker compose build
docker compose run --rm -it reposter
```

Интерактивный запуск нужен один раз, чтобы ввести код Telegram. Сессия сохранится в `./sessions` на хосте. После успешного входа остановите процесс (Ctrl+C) и поднимите его в фоне:

```bash
docker compose up -d
docker compose logs -f
```

`restart: unless-stopped` поднимает контейнер после перезагрузки VPS. `stop_grace_period: 40s` даёт время дослать альбом, который ещё ждёт паузу. Том `./sessions:/data` хранит `reposter.session` и `posted_ids.json` между пересозданиями контейнера.

Обновление кода:

```bash
docker compose up -d --build
```

Два экземпляра с одной сессией запускать нельзя: Telegram разорвёт обе авторизации, а посты могут задвоиться.

## Если не стартует

Код выхода `2` — ошибка `.env` (пустое поле, `VK_GROUP_ID` с минусом, `PHONE` без `+`, положительный `TG_CHAT_ID`).

`Сессия Telegram ещё не создана, а терминал неинтерактивный` — контейнер запущен через `up -d` до первого входа. Выполните `docker compose run --rm -it reposter`.

`Не вижу чат` — аккаунт не в группе или id не от супергруппы.

`VK_TOKEN отклонён (ошибка 5)` — ключ отозван или скопирован не целиком.

Ошибка 15 при `wall.post` — у ключа нет права на стену или сообщество запретило публикацию.

Вложение не появилось на стене — у ключа нет права на фото, документы или видео. Текст при этом может опубликоваться отдельно, если он был в сообщении.

`database is locked` у файла сессии — уже запущен второй процесс с тем же `sessions/`.
